本地建置與檢查

程式會依據既有知識庫資料檢查：

  1. 至少五篇來源，且每篇有原始 HTTPS 網址與筆記。
  2. 每個 Wiki 條目有可追溯的來源編號。
  3. 每張投影片都連到有效 Wiki 條目與來源。
  4. 遇到無效引用時停止產生 HTML，回到條目／簡報資料修改。

實際測試結果：請查看 ZIP 內 CHECK_LOG.md，其中區分成功檢查及故障注入測試。

反思

最需注意的節點：「整理 Wiki → 產生簡報」的來源對應，因為內容看起來合理，仍可能忘記標示原始來源。

將檢查前移：在產生 HTML 之前，先驗證每頁投影片的 sources 與 wiki 欄位，而不是等簡報完成才人工逐頁找缺漏。

Workflow 調整：加入自動檢查閘門；發現無效編號就停止輸出並修正資料，降低錯誤流入成品的風險。

仍需人工完成：LLM Wiki 平台的「先討論、後生成」、五次 ingest 截圖、平台 Wiki 分享連結，以及 GitHub Pages 發布後的 HTML 網址。這些動作不能用本地靜態頁面冒充。
